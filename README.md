# Tmux Rooms

See every tmux session at a glance and get into any of them with one click.

Tmux Rooms is a macOS menu-bar app, plus a command line tool called `tmr`, for
people who run tmux inside iTerm2.

![Opening a room from the menu bar attaches iTerm2 to it](docs/images/tray.gif)

## Why

I keep a lot of tmux sessions open in iTerm2, and tmux is very good at keeping
them alive. Too good, sometimes. A session outlives the task that started it,
detached sessions pile up, and names generated by launchers, like
`agent-20260901023710`, say nothing about what is inside. The commands to sort
it out exist (`tmux ls`, `attach -t`, `kill-session`), but you have to remember
them and run them one session at a time.

Tmux Rooms shows the whole tmux server as a list of rooms. A room is one tmux
session. For each one you can see what is running in it, how many clients are
attached, and when it was last used.

If a room is running Claude Code, Codex, or Antigravity, it is titled with the
name that agent gave the session, so `agent-20260901023710` shows up as "Fix
login redirect". The tmux name is still there, one line down.

From the list you can:

- Open a room. If an iTerm2 window already shows it, that window comes to the
  front. If none does, Tmux Rooms opens one and reuses it next time, so
  clicking Open twice does not leave you with two clients.
- Preview a room read-only, in one iTerm2 tab labelled `READ ONLY` that the app
  keeps reusing.
- Duplicate a window when you do want a second interactive client.
- Delete a room. The app checks that the session is still the one you picked
  before it kills it.

Tmux Rooms never creates a tmux session by itself, and it only touches the
session you acted on.

`tmr` gives you the same list in any terminal:

![tmr picking a room](docs/images/tmr.gif)

## Requirements

- An Apple Silicon Mac with macOS 15 or later
- tmux 3.6b or later from Homebrew, at `/opt/homebrew/bin/tmux`
- iTerm2, for the menu-bar app. Let Tmux Rooms control iTerm2 when macOS asks,
  and turn on iTerm2's Settings > General > Magic > Enable Python API. `tmr`
  works in any terminal.
- Xcode 16 or later to build. XcodeGen 2.46 is only needed if you edit
  `project.yml`.

Tmux Rooms reads the default tmux server, the `default` socket under
`$TMUX_TMPDIR` or `/tmp`. Servers started with `-L` or `-S` do not show up.

## Install

There are no prebuilt binaries yet, so you build from source:

```bash
git clone https://github.com/tellang/tmux-rooms.git
cd tmux-rooms
scripts/install-cli.sh               # tmr and tmuxrooms in ~/.local/bin
scripts/install-local.sh --ad-hoc    # Tmux Rooms.app in /Applications
```

`~/.local/bin` has to be on your `PATH`.

`--ad-hoc` signs the app without a certificate. That is fine for trying it out,
but macOS ties the iTerm2 permission to the signature, so it may ask again after
every rebuild. To keep the permission, create a certificate in Keychain Access
(Certificate Assistant > Create a Certificate, certificate type Code Signing)
and install with `--identity "<certificate name>"`. You do not need to change
its trust settings. With neither flag, the script looks for a certificate named
`Tmux Rooms Local Development`.

Other options:

```bash
scripts/install-local.sh --dry-run --non-interactive   # build and verify, change nothing
scripts/install-local.sh --login                       # also start the app at login
scripts/install-local.sh --no-login                    # stop starting it at login
scripts/install-local.sh --destination ~/Applications/"Tmux Rooms.app"
```

If the app is running, the installer quits it, swaps in the new build, and
starts it again. `--login` writes a LaunchAgent to
`~/Library/LaunchAgents/com.tellang.tmux-rooms.plist`.

## Using tmr

```bash
tmr                    # pick from every room
tmr --here             # only rooms with a pane in this directory
tmr billing            # rooms whose title, tmux name, agent, or path mention billing
tmr -r billing         # attach read-only
tmr ls                 # print the list instead of attaching
tmr ls --here --json   # JSON for scripts
tmr -help
```

In the picker, Up and Down (or `k` and `j`) move the highlight and wrap around,
Home and End jump to the ends, and Enter attaches. A number attaches to that
room straight away; with ten or more rooms, type both digits, or one digit and
Enter. `q`, Esc, and Ctrl-C cancel. The highlight starts on the first room with
a pane in the current directory, and the list is drawn on stderr so stdout stays
clean.

When only one room matches, `tmr` attaches without asking. Text matches a room's
title, tmux name, agent, or pane paths, ignoring case, and a tmux name or
session id that equals the text exactly wins over partial matches.

Attaching works like `tmux attach-session`: it adds a client, so a room that is
already open in another terminal ends up with two clients sharing one screen.
Inside tmux, `tmr` switches the current client instead. `-r` is refused there
because a read-only view would need tmux inside tmux.

Rooms running `claude`, `codex`, or `agy` show the agent in an AGENT column, in
orange, white, and blue. Colors need `COLORTERM=truecolor` or a `256color`
`TERM`, and `NO_COLOR` turns them off.

`ls` can also be spelled `list`, and `attach` can be spelled `a`. The short name
is `tmr` rather than `tr` because `tr` is a standard Unix command.

| Exit code | Meaning |
|---|---|
| 0 | Success. `tmr ls --json` prints `[]` and exits 0 when nothing matches. |
| 1 | No match, cancelled, or several matches and no terminal to pick in |
| 2 | Usage error |
| 3 | tmux could not be read, for example because it is older than 3.6b |
| 126 | tmux could not be started |

## JSON output

`tmr ls --json` prints an array of rooms.

| Room field | Contents |
|---|---|
| `id` | tmux session id, such as `$3` |
| `name` | tmux session name |
| `title` | the title shown in the list |
| `agent` | `claude`, `codex`, `agy`, or `null` |
| `paths` | working directories of the panes |
| `interactiveClients`, `readOnlyClients` | attached client counts |
| `lastActivity` | last activity as Unix time in seconds |
| `panes` | one entry per live pane |

| Pane field | Contents |
|---|---|
| `paneId` | tmux pane id, such as `%12`. It stays the same for the life of the pane, so use it to address a pane. |
| `target` | `session:window.pane`, such as `work:0.1`. Handy for `tmux -t`, but it points somewhere else if windows are renumbered or panes move. |
| `active` | whether this is the active pane |
| `path` | working directory |
| `agent` | `claude`, `codex`, `agy`, or `null` |
| `pid` | the agent's pid, or the pane's pid when there is no agent |
| `sessionId`, `name` | the agent's session id and name, or `null` |
| `state` | `busy`, `idle`, or `unknown` |

Claude's state comes from its session registry. For Codex, `tmr` reads the
bottom of the pane: `esc to interrupt` means busy, and the input prompt with
nothing running means idle. `agy` is busy or unknown, because it has no idle
marker that has been checked. Anything else is `unknown`. The screen is only
read for `ls --json`, and state is never guessed from a process name.

## Where agent names come from

Tmux Rooms only reads these files, plus the tmux pane title for Claude Code.
When none of them has a name, the room is labelled `Claude`, `Codex`, or
`Antigravity`, and a room with no agent keeps its tmux name.

- Claude Code keeps `~/.claude/sessions/<pid>.json` (under `$CLAUDE_CONFIG_DIR`
  when that is set), which records the name set with `/rename` and the pane
  the session runs in. A session nobody renamed falls back to the conversation
  title in its transcript. A background session viewed through `claude agents`
  records no pane, so that pane is named from the title Claude Code wrote into
  it, without the leading status glyph. An empty title, `Claude`,
  `Claude Code`, a `claude` command line, or the host name tmux gives a new
  pane is ignored.
- Codex thread names come from `$CODEX_HOME/session_index.jsonl` (`~/.codex`
  by default), and the last rename wins. To work out which thread a pane is
  running, Tmux Rooms checks the registry the triflux launcher writes at
  `$XDG_STATE_HOME/triflux/codex-sessions/<pid>.json` (`~/.local/state` by
  default). `tmr` then checks the rollout file the codex process has open,
  found with `lsof`. Last comes `.omx/state/session.json`, which oh-my-codex
  writes in the pane's directory or one of its parents up to your home
  directory.
- Antigravity is recognised by its `agy` command and has no name source.

A record counts only when its pane matches a live pane and its pid is the
pane's process, or a descendant running that same agent. A file left behind by
a finished session cannot name a room.

These files belong to other tools, and their formats are not documented as
stable. If one of those tools changes its format, names from it stop showing
until Tmux Rooms catches up.

## Files and permissions

The app asks macOS for permission to control iTerm2. It writes two things:

- `~/Library/Application Support/Tmux Rooms/ManagedClients/`, a record of the
  iTerm2 clients it opened, so it can find them again after a crash
- `~/Library/Application Support/iTerm2/Scripts/com.tellang.tmuxrooms-title.py`,
  the iTerm2 script that sets the `READ ONLY` tab title

iTerm2's Python API lets local programs script iTerm2. Keep that in mind if
other people use your Mac.

## Troubleshooting

Logs from the app:

```bash
log show --last 30m --predicate 'subsystem == "com.tellang.tmuxrooms"' --style compact
```

- The Preview tab has no `READ ONLY` title: the iTerm2 Python API is off. Turn it
  on and click Preview again.
- `tmr` exits with 3: tmux is older than 3.6b, or it is not at
  `/opt/homebrew/bin/tmux`.
- A server is missing from the list: it was started with `-L` or `-S`.
- macOS asks for the iTerm2 permission after every rebuild: install with a
  certificate, as described under Install.

## Uninstall

```bash
scripts/uninstall.sh --dry-run   # list what would be removed
scripts/uninstall.sh             # asks for confirmation, or pass --yes
```

The script quits the app, then removes it along with `tmuxrooms`, the `tmr`
link, the login LaunchAgent, the app's state folders, and the iTerm2 script. It
does not touch your tmux sessions.
